# Multiple-Model Comparison

Category ID: `mutl-comparison` (the requested spelling). `multi-comparison` is an accepted alias. Choose this category for a single metric across multiple methods. Use `multi-metric-comparison` for multiple metrics in one figure.

## Input contract

- `data_mode: raw`, `layout: long`: `model` and numeric `value` columns, optionally an `id`. Each row is one observation for one method. `paired: true` requires nonmissing unique model/ID keys and identical ID sets. Independent observations use `paired: false`.
- `data_mode: raw`, `layout: wide`: provide a named `model_columns` mapping (method label to score column), plus `id` when paired. One row is one observational unit. This layout supports a single metric.
- `data_mode: summary`: one row per model, with `value` referring to its mean or pooled score. Optional `sd` and `n` columns contain actual standard deviations and sample sizes. Never invent uncertainty or reconstruct distributions from means and SDs.
- Optional `filter` maps a column to accepted values, e.g. `{"row_kind":"observation"}`. Exclude precomputed aggregate rows before calculating summaries. Optional `metric` plus a one-element `metrics` selection supports long multi-metric files.
- Relative paths resolve against the configuration. Use the usual external input and figure-specific output folder conventions.

Inspect the current source instead of requiring the user to preformat it. Use the native long/wide support above when valid. Unexpected metric columns or transposed summary tables can use [input preparation](data-preparation.md); save the mapping and transformation with the external figure. Preserve lexical model/ID values, including leading zeros, precision, raw-versus-summary meaning and pairing. Scientific ambiguity requires consultation rather than an automatic average, inferred SD or row-order match.

## Choose the display

| `style` | Suitable input | Marks |
| --- | --- | --- |
| `bar` | Raw observations or summary means | Mean bars; optional raw observations and mean ± SD |
| `box` | Raw observations only | Solid median/quartiles and 1.5-IQR whiskers; show all outliers; optional jitter and a separate diamond mean marker and ± SD overlay |
| `violin` | Raw observations only | Trimmed density; optional jitter and mean ± SD; dashed quartiles, a solid median, and an optional mean diamond with SD |
| `line` | Raw observations or summary means | Line joining method means with a small mean symbol at each method; optional SD, with no raw scatter |

Both `orientation: vertical` and `horizontal` are supported. Model connections in a categorical line plot communicate comparison order, not a time trajectory. `line_markers` defaults to true, with a small filled diamond (`line_marker_shape: 18`, `line_marker_size: 1.3` mm for ordinary means). Paired `delta: true` reference-difference lines instead start at 2.3 mm; an explicit `line_marker_size` overrides either starting size. These symbols mark the method means, not raw observations; they remain present whether SD is shown or omitted. Explicit `line_markers: false` requests a plain line. Shape can be any integer R point symbol from 0 to 25, and size is configurable. `show_points` applies only to non-line raw plots. Lines default to dashed.

For `delta: true`, require `paired: true`, `id`, and a named `reference`. Calculate each observation minus its matched reference before summarizing. Show a dotted zero baseline and retain the reference at zero. The error bars are the sample SD of the paired differences, not the difference between group SDs. Both a lower-is-better and higher-is-better metric retain their original difference sign.

## Values, ranking, and colors

All single-metric figures display three-decimal means (signed means for deltas) and a Performance Ranking arrow by default. `direction` is `higher` or `lower`; `sort: performance` puts the best model on the left in vertical figures; horizontal figures retain worst-to-best top-to-bottom order. `reverse-performance` reverses this order and the arrow. An explicit `model_order` always takes precedence over automatic sorting; `sort: input` otherwise uses source order. An arrow requires monotonic values: a fixed non-ranking order must explicitly set `show_rank: false`. Ties share rank; do not imply a significant difference. The ranking arrow and its text always accompany numeric values on the same side and in the same block. If values move into the lower interior strip for a vertical significance display, ranking moves there too; passing significance stays above. Do not leave an isolated ranking axis opposite its values.

Vertical paired-difference lines use tighter top annotations (`rank_offset: 0.055`, `value_offset: 0.105`, `rank_text_gap: 0.020`) with larger 2.3 mm mean diamonds. Explicit offsets and marker sizes remain authoritative; inspect the numeric row and arrow together at final print size.

Horizontal bars with an arrow start with `rank_offset: 0.04`, `value_offset` 0.03 above that offset, and `rank_text_gap: 0.04`. After flipping coordinates, values sit just to the right of the arrow and the rotated ranking text sits just to its left. All offsets are fractions of the numeric-axis span. Preserve explicit user/saved values, and inspect the gap at final print size so the line does not touch text. Horizontal box/violin and vertical defaults retain their own spacing.

`highlight` names the focal model(s); its numeric label is red and bold. Without it, highlight the best mean as a numeric annotation; this does not reserve its hue. Automatic method colors use the [fixed focal/comparator policy](palette-contract.md#fixed-categorical-slots), based on an explicit visual focal or exact raw ID `Ours`, independently of performance. Highlighting a focal model does not assert it is best. Preserve actual names with `model_labels`, and preserve colors across related figures using a complete named `color_values` mapping. Choose `rainbow` for the muted ten-color palette, or the existing green-blue-purple palette.

## Axes and transparency

The default `axis_policy: auto` selects `zoom` for bars and `full` for boxes, violins and lines. Zoomed bar limits sit slightly below/above the complete displayed extent, including any shown points and SD; they do not always begin at zero. `zero` explicitly includes zero; `full` requests the full style view, including zero for bars. `zoom` uses the displayed numeric extent with configurable `occupancy` of 0.90–0.95. `bar_min_fraction: 0.15` targets a shortest visible bar of 15% of an eligible automatic positive/negative zoomed view, including external-value layouts. Respect zero/domain/baseline constraints; zero-length or scientifically fixed bars do not receive an artificial origin. Explicit limits and zero/full policies remain unchanged. On a positive bar chart it draws bars from the visible lower bound and records the truncated baseline in the statistics. A zoomed bar is not a ratio-of-length comparison. Always disclose truncation in the delivery or figure legend; use clear labeled ticks. Never crop observations, outliers, or SD intervals to make the focal model look stronger. Use a full-range box/violin view when distributions are broad. Explicit `limits` that hide data or uncertainty are rejected. Automatic breaks use the physical axis length and measured Arial label widths; coarsen crowded intervals rather than forcing a 0.05 step. Explicit `breaks` remain available.

Dense jitter may use smaller points and adjusted jitter, while palette opacity stays fixed unless the user requests a change. Points default to alpha 0.55 and color darkening 0.20 in this category, with reproducible jitter (`seed`). A null `point_size` resolves after filtering/missing handling to 0.36 mm when the densest method/metric group has at least 200 observations, otherwise 0.48 mm. Explicit size overrides this heuristic. The default palette is `rainbow-transparent`. Box/violin summaries and SD marks must remain distinguishable. SD is descriptive variability, not SEM, CI, or a significance test. No statistical test is inferred from visual ranking. Requested tests use the separate opt-in behavior below.

## Missing predictions

Default `missing: error`. Explicit `drop` records discarded rows and still enforces matching IDs when paired. `penalty` requires an explicit numeric bound. An `availability` column with `unavailable_values` flags failed predictions even when numeric placeholders already exist. Record original values and the `penalized` flag for every plotted row. Incomplete absent rows must be completed by an explicit, saved preprocessing step before plotting. Choose penalty bounds from the metric definition and user instructions, not a convenient observed extreme. Any preprocessing must preserve pairing and document its denominator.

For a short request without a selected style, follow [the consultation workflow](autonomous-workflow.md#consult-before-rendering). Clarify materially different display choices when they are not established; an explicit request to choose automatically or produce alternatives permits selection without another question. Use `scripts/render_candidates.R` to generate eligible alternatives from one validated configuration.

## Configuration and adaptation

Start with [the example](../examples/multi-comparison/request.json). Key layout controls include `layout_columns`, `width_mm`, `height_mm` (preferred), legacy `width`, `height`, `title_size`, `axis_title_size`, `axis_text_size`, `category_text_size`, `value_size`, `rank_size`, `right_margin`, `annotation_gap`, `panel_tag`, `label_angle`, `bar_width`, `line_markers`, `line_marker_shape`, `line_marker_size`, `point_alpha`, `point_size`, and `fill_alpha`, `outline_width`, `inner_width`, `sd_width`, `mean_width`, `border_alpha`, `point_darken`, `category_padding`, `rank_offset`, `value_offset`, and `rank_text_gap`. All text uses Arial. Titles and metric units are supplied by the user; do not infer them from an unrelated example. Omitted cosmetic controls resolve the selected visual profile in code. Four-column output starts at 42 × 38 mm with category labels 5.7 pt, numeric values 1.9 mm, ranking text 1.8 mm, title 7 pt, axis title 6.5 pt and ticks 5.5 pt; measured rotation remains automatic. Three-column figures requesting significance start at 57 × 54 mm. Explicit dimensions/fonts remain valid and statistics retain the resolved `visual_profile`.

`label_angle: auto`, `value_angle: auto` and `label_wrap: auto` use measured Arial widths at the final font/canvas size. Vertical method/value labels choose readable 0°, 45° or 90° angles; method names can wrap. Horizontal names can wrap to retain at least `text_min_panel_mm: 12` of useful panel width, with a starting `text_fit_gap_mm: 0.7`. Explicit numeric angles from -90° to 90° are honored; `label_wrap: none` disables wrapping. Impossible fits fail with guidance to widen the canvas or provide shorter display labels, rather than clipping or shrinking text. Resolved configuration saves the chosen numeric angles; `statistics.text_fitting` retains policies, displayed labels, wrapping, candidates, measured millimeter fit and the decision reason. This applies to bars, boxes, violins and lines.

The script exports PDF, SVG, PNG, resolved configuration, plotted data, per-model summary CSV, statistics and session records. Inspect the actual preview and representative vector output; refine label spacing, point size and canvas size while preserving the fixed palette contract. When several styles are plausible or requested, render multiple candidates in separate figure folders using consistent observations, colors, ordering and penalties. These templates are starting points: accept targeted per-figure revisions and keep dataset-specific choices out of universal defaults.

## Palette and category spacing


Fill opacity is palette-specific: 1.00 for `rainbow`, `blue-yellow` and `blue-pink-purple-peach`; 0.40 for their transparent variants and `muted-green-blue-purple`; 0.25 for `muted-green-blue-purple-transparent`. Explicit `fill_alpha` overrides these defaults; reset it to null to use the selected variant. A null `category_padding` uses vertical defaults of 0.50 for boxes (at least the half-width plus clearance), 0.58 for violins, bar half-width + 0.18, and 0.46 for lines; horizontal defaults retain their existing mark-aware clearance; avoid adding expansion again through coordinate limits. Titles are centered across the full canvas, including ranking annotations. Inspect outer values and long category labels for clipping.

## Optional one-sided significance

Set `show_significance: true` and `significance_model` to an explicitly designated focal method (or supply exactly one explicit `highlight`). Never select the focal method retrospectively from the observed winner. The alternatives are focal > comparator for `direction: higher` and focal < comparator for `direction: lower`.

- Paired raw input uses one-sided paired t-tests with ID matching. Independent raw input uses one-sided Welch t-tests.
- Compare against **every other displayed method**, including a displayed reference. Draw the complete set of compact `p < 0.05` brackets only when every test passes the threshold. Otherwise draw none; preserve all computed results and the reason in statistics JSON.
- Summary/pooled scores do not enable this test. Untestable data, including degenerate variance, cannot pass the all-comparisons gate.
- `p_adjust: none` is the default requested per-comparison test. `p_adjust: holm` optionally uses Holm-adjusted values for the threshold. Record the chosen method and retain both full-precision raw and adjusted p-values; the annotation alone is not a claim of multiplicity correction.
- `significance_size` defaults to 1.8 mm; `significance_spacing_mm` starts at 2.7 mm for horizontal significance and 2.2 mm for vertical significance, preserving explicit/saved values. Brackets use physical spacing and reserve extra annotation space. Inspect compact vertical and horizontal examples in the gallery.
- `annotation_layout: auto` is the default. When both values and passing significance are displayed, horizontal comparisons put values on the right and brackets in an empty interior strip left of the marks but right of the left axis. Vertical comparisons put brackets above and the complete value/ranking block in an empty interior strip below the marks but above the bottom axis. A single displayed annotation retains the right/above position. Reserve readable annotation space without hiding observations or SD; the horizontal brackets must not enter the model-name column, and vertical values must not enter the tick-label area. `same-side` explicitly restores the legacy right/above arrangement. `significance_gap_mm` starts at 0.6 mm, with 0.35 mm caps and reservation derived from measured Arial glyphs. Each bracket anchors to the complete displayed extent of the methods in its comparison/span, including shown points and SD, rather than the view boundary or an unrelated method. Account for the numeric/ranking block when annotations share a side. With no explicit `category_padding`, horizontal significant box/violin figures start at 0.62 category units to increase top/bottom clearance. Resolved annotation placement is recorded in statistics; inspect every export.
- The interior strip is sized automatically using actual Arial panel/font measurements, or an explicit `annotation_strip_mm`. Horizontal significance views need not start at zero: begin just beyond complete displayed distribution/SD support and the measured bracket strip when safe, avoiding unrelated empty range without cropping observations. `metric_domain` optionally supplies two established scientific bounds; never infer them from the observed range. Prefer a safe empty strip within those bounds, but extend the view and record `axis_note` if full observations/SD or annotation glyphs need more room. The effective internal bracket gap can reduce from 0.6 mm, never below 0.4 mm, when safely fitting a stated domain. Original `data_limits` and expanded display `limits` remain separate in resolved configuration. Statistics record the shown data extent, both limit sets, panel size, reserved strip and numeric strip bounds, effective gaps and sides. Bars keep their baseline flush with the axis; applicable interior labels sit near the baseline within bars rather than creating a data-to-axis gap. Clear inherited data/display limits when recalculating for new data. Horizontal box/violin clearance applies when significance is requested even if the display gate fails; failed tests still draw no brackets.
- The t-test assumes independent observational units (paired differences for paired data). Repeated measurements from one source may require an explicitly chosen aggregation or a different dependence-aware analysis. Pairing alone does not establish independence. Keep this limitation in per-figure records when relevant.


## Optional broken numeric axis for boxes

Set `axis_break: [lower, upper]` for raw `style: box` data only. This is an explicit open interval: its two endpoints remain eligible observations and ticks. Both horizontal and vertical orientations are supported. The renderer compresses the empty interval into a narrow visual gap, draws a double slash across the numeric axis, retains labeled original-value ticks on the visible segments, and automatically adds a caption disclosing the omitted interval. Exported observations, summaries, distribution quartiles, whiskers and statistics keep their original values; the change is a display transformation only. Never interpret visual distances across the break as ordinary numeric distances.

Every observation must be outside the open interval. No complete box/whisker span or displayed mean ± SD interval may intersect it, even when all observations lie on the two sides. Break endpoints must lie strictly inside the final numeric limits. The renderer rejects unsafe breaks instead of deleting observations or shortening boxes/uncertainty. The explicit interval must follow the intended scientific display; it is never selected automatically from favorable results. Omitted-range disclosure is mandatory and appended to any supplied caption. `axis_break` also works in the comparable `grouped-distributions` box layout.

Value labels and ranking arrows resolve off when a break is requested. Explicit requests for those annotations or significance brackets are rejected because their existing placement contract assumes one continuous linear scale; use a separate continuous-axis view for these annotations. Breaks are not supported on bars, violins, lines, summary-only data or other combined layouts. If the retained segments or caption are crowded, widen/tall the figure and inspect the actual exported image. The minimal [broken-box configuration](../examples/broken-box-vertical/request.json) uses a clearly synthetic interval, not a default range for new data. Inspect the fixed-data [horizontal](../examples/broken-box-horizontal/preview.png) and [vertical](../examples/broken-box-vertical/preview.png) previews, labeled with their actual palettes.


Broken-axis automatic ticks are fitted after compression using actual Arial label widths (horizontal) or heights (vertical), the final physical panel length and at least 0.7 mm adjacent clearance. Coarsen automatic candidates without changing scientific values; retain at least one labeled tick in each visible segment. Explicit tick sets that overlap fail with a request to coarsen ticks or enlarge the canvas. Horizontal endpoint half-widths and vertical endpoint half-heights reserve measured canvas gutters, including when no title creates a top row. Custom captions and the mandatory disclosure wrap using final panel width; oversized unbreakable tokens require a wider canvas or clearer shorter text.
