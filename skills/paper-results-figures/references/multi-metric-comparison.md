# Multiple-Metric Comparison

Category ID: `multi-metric-comparison`. Compare multiple metrics across the same methods using a layout whose axes preserve their meaning. Parallel bars, stacked bars, facets and dual axes compare exactly two metrics; `shared-axis` and `grouped-distributions` support two or more metrics with identical units and an established common scientific range. Read [the common multiple-model specification](multi-comparison.md) for raw/summary inputs, pairing, missing penalties, colors and exports.

Use long input with `model`, `metric`, and numeric `value` columns. Set `metrics` to the displayed metric IDs. Optional summary `sd` and `n` columns follow the same contract. Each metric must contain the same models; paired input must retain each model's matching observational IDs. Use one common `model_order`; per-metric sorting cannot produce one common categorical axis. Every combined layout derives an omitted performance order from `combo_order_by` (the first metric by default), using that metric's established direction. Explicit `sort: input` and `model_order` remain authoritative. Record the ordering metric; do not infer a common ranking from unlike metric orders. `combo_labels` optionally maps metric IDs to display names.

When the source instead contains separate metric columns or a transposed metric/model summary table, inspect its meaning and adapt it using [input preparation](data-preparation.md). Preserve precision, method identity, raw IDs or actual supplied SD/count fields. Save the explicit transformation in the external figure folder; do not treat pooled metric cells as replicate observations.

## Choose the layout

An explicit `highlight` remains visible in facets, dual-axis and shared-axis layouts through red bold method-axis labels, including when numeric values are omitted. This does not change model or metric colors.

| `combo_layout` | Purpose and supported marks |
| --- | --- |
| `facets` (default) | Two aligned vertical panels with independently labeled numeric scales; `combo_styles` selects bar or line for each metric |
| `shared-rows` | Two parallel horizontal bar panels; model names appear once at the left; values may stay outside or use larger internal text |
| `stacked-bars` | Two vertical bar panels placed one above the other; common model order, model names only on the bottom panel, wider bars with outer side clearance |
| `shared-axis` | Two or more mean lines on one numeric axis; identical units and established scientific range, metric colors/linetypes and a mean symbol per method |
| `dual-axis` | One bar and one line overlaid with a recorded affine transformation and explicitly labeled primary/secondary axes |
| `grouped-distributions` | Consecutive clusters of two or more comparable metrics; model colors and a measured inside/external model legend; uniform bar/box/violin marks in either orientation |

The dual-axis model-color mode uses a measured, automatically wrapped subtitle with metric names to identify its bar and line metrics; original units stay on the axes. `combo_color_by: model` uses the [fixed focal/comparator hue mapping](palette-contract.md#fixed-categorical-slots), keeping the designated focal method visually distinct from every automatic comparator across metrics and orientations. Optional `combo_color_by: metric` uses one fixed color for the whole bar metric and a second fixed color for the whole line metric, with a compact measured top legend and metric names only, replacing the duplicate subtitle. The bar key is a rectangular color block; the line key uses the same shape, size and color as the plotted mean icon (`line_marker_shape` and `line_marker_size`, default a 2.0 mm diamond). Do not add bar/line prefixes to the metric names. It starts at axis-tick text size (6 pt) with 3 × 2 mm keys, one row when readable or two when needed; `metric_encoding.legend` records its fit and key type. In the blue-yellow family with exactly one bar and one line metric, an omitted metric-color map selects existing light-blue slot 3 (`#B5D0E0`) for bars and yellow slot 2 (`#F5C258`) for the line/icons; palette opacity and every RGB definition stay unchanged. `combo_metric_colors` can provide a complete named metric-to-color map and always takes precedence. Other palettes assign fixed slots deterministically to metric IDs. Preserve the resolved named map across related figures. Secondary-axis alignment is a display choice; do not infer correlation from it. If correlation is scientifically requested, compute it from an appropriate observational unit separately. Use facets when independent scales provide a clearer comparison.

Optional mean ± SD and raw points on bar layers are supported. Line layers show a symbol at each method mean by default (`line_markers: true`, filled diamond shape 18): 2.0 mm in dual-axis/shared-axis layouts and 1.3 mm in facets. An explicit false value requests a plain line. `line_marker_shape` and `line_marker_size` control its appearance. Raw observations are never scattered on a line layer. Combination figures do not require the single-metric numeric labels or ranking arrow. These layouts use long raw/summary data without paired-delta mode. Use the single-metric category for one distribution metric or paired deltas, and `grouped-distributions` for multiple comparable distribution metrics.

With canvas controls omitted, the three-column visual profiles start at 114 × 46 mm for two facets, 76 × 54 mm for shared rows with outside values or 70 × 54 mm with inside values, 70 × 54 mm for stacked bars, 70 × 46 mm for shared-axis mean lines, and 57 × 46 mm for dual axes. Dual-axis category labels start at 6 pt. Explicit dimensions, column settings and saved per-figure controls remain authoritative; inspect long labels and actual data at export size. The statistics record's `visual_profile` retains resolved dimensions, fonts, bar width/category padding and line-icon size. These defaults are applied in the renderer, not copied from completed synthetic runs.

`show_sd` controls the general display request; `combo_show_sd` can override visibility with a named boolean per metric. The dual-axis default retains SD on the bar when requested and omits SD on the line, keeping its mean symbols visible. Other layouts follow `show_sd` unless overridden. Hiding an overlay never changes stored SD, observations or means. Real SD always comes from the actual observations or supplied SD column; never change its computed value, substitute SEM/CI, or alter data to reduce overlap. `combo_sd_display: auto`/`both`/`outward` is an explicit visual policy for bar SD: keep its category coordinate centered on the method; `both` shows both halves, `outward` the half away from the bar baseline, and `auto` uses the full symmetric interval with outside values and selects the outward half only when requested internal value text would overlap the symmetric SD. The outward interval is mean to mean + SD above the visible baseline, or mean − SD to mean below it. Store the full SD unchanged and record the displayed half/policy in `sd_display_by_group`, including `computed_sd`, `full_lower`/`full_upper` and `shown_lower`/`shown_upper`. This is a mean ± SD display choice, not a different uncertainty calculation.

Start with [the shared-row example](../examples/multi-metric-shared-rows/request.json), or select the focused configuration for [larger internal shared-row values](../examples/multi-metric-shared-rows-inside/request.json), [stacked bars with outside defaults](../examples/multi-metric-stacked-bars/request.json), [shared-axis mean lines](../examples/multi-metric-shared-axis/request.json), or [dual axes with metric colors](../examples/multi-metric-comparison-dual-axis-by-metric/request.json). Inspect the scales, method order, marks and labels. A template remains adjustable to the actual scientific purpose; per-figure refinements belong in its external configuration.

The common measured text-fitting controls (`label_angle`, `value_angle`, `label_wrap`, `text_fit_gap_mm`, `text_min_panel_mm`) apply across layouts. Defaults use actual Arial widths at final export size; explicit angles/wrapping are honored. Values default to `combo_value_placement: outside`, preserving external shared-row labels at `value_size: 2.2` mm. Requested `inside` uses `combo_inside_value_size: 2.7` mm and measured internal placement/rotation. Adapt automatic baseline padding/view until every requested internal label fits and remains clear of the displayed SD; do not relocate those labels outside. Explicit fixed limits cannot change silently; if their dimensions make an internal label impossible, require canvas/limit refinement. Save per-metric `combo_axes.inside_padding` original/resolved limits and reasons, and each `inside_value_placement` label's measured width/angle/placement. Resolved inside runs retain `value_angle: auto` when rotations differ per bar; their exact angles are stored with those placements. Automatically saved `combo_sd_modes` maps metric IDs to model-to-`both`/`outward` decisions so a saved padded view reproduces the same SD display. These are reproducibility records, not additional routine questions; clear inherited resolutions when recalculating unrelated data. `combo_panel_gap_mm: 2.0` is the starting physical gap between panels. Outside shared-row values use a 0.45 mm physical gap from each numeric panel and reserve their complete measured text width plus export clearance. Automatic method labels rotate when that reduces the measured name-column width and every label remains clear in its row. Shared rows additionally reserve a right gutter of at least 3.0 mm for inside values, expanding to the measured endpoint tick-label half-width plus 0.35 mm when necessary; this preserves labeled endpoints without changing the numeric axis. Inspect actual tick/label clearance. See [the common specification](multi-comparison.md#configuration-and-adaptation) for fit behavior and recorded decisions.

## Horizontal parallel metrics with shared model labels

Use `plot_type: multi-metric-comparison` and `combo_layout: shared-rows` for two side-by-side horizontal bar panels with one model-name column at the far left. Every model occupies the same row in both panels. The panels have equal plotting widths, independent labeled numeric axes, shared model colors, three-decimal values and one title centered over the full figure. Values are external by default; `combo_value_placement: inside` uses larger text within readable bars for a more compact combination. Optional focal values are red in both panels. Raw observations and sample SD are supported when available; pooled values never imply SD.

The layout defaults to horizontal orientation, two bar styles, 76 mm total width for external values or 70 mm for internal values, 54 mm complete height, and no ranking arrows. When combining existing figures, preserve their requested height, including title and axes. A wider combined canvas is intentional and is not one standard single-panel slot. Inspect at final print size.

- Use one common model order. Explicit `model_order` is honored; otherwise `sort: performance` sorts by `combo_order_by` (default: the first metric), using `direction` for that ordering metric. Horizontal default order puts the best model at the bottom, consistent with the single-metric horizontal example. `sort: input` preserves input order. Record the ordering metric in the figure notes.
- Never independently sort the two panels: that would break row alignment. Do not draw a common performance-ranking arrow when the two rankings differ. The default is `show_rank: false`. On explicit request, `show_rank: true` draws one arrow at the far right only if both metrics improve monotonically in the same displayed direction; otherwise rendering stops. `combo_directions` can map each metric ID to `higher` or `lower` (omission uses `direction` for both). Values remain available with `show_values: true`.
- `combo_limits` and `combo_breaks` are optional objects keyed by metric ID. Omit them to derive separate ranges and adaptive ticks. Single `limits`/`breaks` are rejected to avoid accidental reuse on unlike metrics. `axis_policy: auto` uses zoomed bar extents with small padding below/above the complete displayed values, SD and raw points. It does not always start at zero. Explicit `zero`, `full` or `zoom` remains available. For eligible automatic positive/negative zoomed bars, `bar_min_fraction: 0.15` targets a shortest visible bar of 15% of the numeric span, including outside-value layouts. Respect zero/domain/baseline constraints and explicit limits; do not invent a negative origin or promise this length for zero-length bars. Requested internal values can need additional measured baseline padding. Bars start flush at their visible axis baseline; save and disclose every nonzero baseline.
- `combo_labels` maps metric IDs to displayed axis names. `combo_styles` must be `["bar", "bar"]` for this layout. Other layouts retain their bar/line options. Significance brackets and paired deltas are not supported here.
- If the source is wide (one row per model and one column per metric), use the optional `metrics-wide-to-long` preparation operation or save an equivalent reproducible transformation in the external figure folder. Preserve original precision and model IDs. Use `data_mode: summary` for pooled/mean-only scores, or raw mode with observational IDs when genuine replicates exist.

See the [generic configuration](../examples/multi-metric-shared-rows/request.json) and [synthetic preview](../examples/multi-metric-shared-rows/preview.png). Per-figure changes to dimensions, titles or spacing remain supported without changing the default palette contract.

Automatic shared-row axes complete a nearby outer tick using the shared 20%-of-interval rule. Apply this after final baseline and inside-label padding, using the final readable tick interval; recheck internal text fit after completion. User-requested common tick sets and limits override this heuristic; common limits must include both metrics in full.

## Stacked vertical bars with shared labels

Use `combo_layout: stacked-bars`, `orientation: vertical` and two bar styles. The two metrics occupy vertically aligned panels in a single figure; each method keeps its x position and model color, and labels appear only beneath the bottom panel. Use one common order, with best-on-left ordering by `combo_order_by` when sorting by performance. Independent numeric axes retain each metric's identity; comparable metrics may share explicitly requested bounds/ticks.

Start at 70 × 54 mm complete size. Wider `bar_width: 0.84` reduces gaps between bars; outer `category_padding` starts at bar half-width + 0.28, giving 0.70 at that default, to retain more space beside the first/last bars. These controls resolve independently and explicit overrides remain valid. Inspect the first/last bars, labels and final printed width. Values default outside; request larger internal values with `combo_value_placement: inside` and keep every label inside through measured geometry refinement. `show_sd: false` or per-metric `combo_show_sd` can omit SD without changing the calculations. Automatic axes use the actual displayed extent with padding rather than forcing a zero origin. Keep all currently displayed uncertainty and points visible.

## Multiple mean lines on one comparable numeric axis

Use `combo_layout: shared-axis`, two or more metric IDs, and a line style for every metric. Explicitly supply `combo_units`, a named map of equal nonempty unit descriptions, and `combo_domains`, a named map whose established two-endpoint scientific bounds are identical for every metric. Equal observed ranges alone do not establish comparability. Unlike units or definitions require facets or separate views, without hidden normalization or rescaling.

Use one common method order rather than independently sorting each metric. Each metric has a fixed color/linetype and appears in the legend; each method mean has a 2.0 mm icon by default. Model-color assignment used for bars is distinct from this metric-color encoding. An explicitly designated `highlight` method remains visible through its red bold method-axis label when numeric mean labels are omitted; metric colors are unchanged. Means use their original values; all lines share the same numeric scale. `show_sd` and per-metric `combo_show_sd` control actual SD visibility. This layout omits numeric value labels and ranking arrows (`show_values`/`show_rank` resolve false), keeping metric mean lines and their legend readable. `combo_metric_colors`, `combo_line_types` and `combo_marker_shapes` optionally map every displayed metric ID to its fixed color, linetype and mean icon; defaults use deterministic metric palette slots and distinct patterns/shapes; shared-axis always resolves `combo_color_by: metric`. Use one `limits`/`breaks` pair for the common numeric view; per-metric `combo_limits`/`combo_breaks` are rejected. Inspect crossing lines, symbols, legend placement and common ticks at final size.

### Optional bars beneath shared-axis mean lines

Set `combo_bars: true` with `combo_layout: shared-axis` to draw one bar underneath each mean icon, retaining the line connecting that metric across methods. The same explicit comparable units and scientific domains remain required. All bars begin at zero, and the common axis must retain zero and every displayed value/SD; there is no hidden rescaling. Each metric has one fixed color for its bar, icon and line. Metric centers are separated within each method using `combo_bar_width: 0.72` total category units by default; this denser bar-and-line profile uses 1.6 mm mean icons, and icons and error bars stay centered on their own bars. The saved scientific values and method ticks remain unchanged. All methods retain one common order. A request with too many symbols for the physical allocation fails with guidance to widen the figure or use facets, preserving readable mean icons. `metric_encoding.bars` records the zero baseline and total category width; `category_series_offsets` records the displayed metric centers. The option is off by default and rejected for other layouts.

### Descriptive correlation on dual axes

Metric-colored dual axes default to `show_mean_correlation: true`. The statistic is Pearson correlation between the original two metrics' method means, matched by method identity before the secondary-axis affine display mapping. Its sampling unit is one displayed method, rather than one raw observation. The annotation shows `Mean Pearson r` to three decimals and the number of matched methods; this is descriptive and carries no p-value or claim of observation-level independence. Constant means or fewer than two methods yield an explicitly undefined correlation. `show_mean_correlation: false` omits this annotation, and an explicit true request is supported for model-colored dual axes too. Other layouts reject this option.

The complete correlation text uses actual Arial geometry on every export device. It searches measured empty space clear of bars, SD and line/mean icons; when no safe rectangle fits, a measured row above the panel keeps the statistic readable within the established complete canvas. Small allocations that cannot retain a readable panel fail rather than overlap or shrink text. `statistics.mean_correlation` retains the full-precision coefficient, matched original means, metric identities, method count, definition status and descriptive interpretation. `mean_correlation_placement` records per-format geometry, safe-space bounds or the external fallback reason. The secondary-axis mapping does not enter the calculation.

The [dual-axis metric-color preview](../examples/multi-metric-comparison-dual-axis-by-metric/preview.png) and [configuration](../examples/multi-metric-comparison-dual-axis-by-metric/prompt.md) demonstrate one fixed color per metric while retaining separate labeled axes.

See the [shared-axis preview](../examples/multi-metric-shared-axis/preview.png) and [configuration](../examples/multi-metric-shared-axis/prompt.md). The gallery also includes [larger internal shared-row values](../examples/multi-metric-shared-rows-inside/preview.png), [stacked bars](../examples/multi-metric-stacked-bars/preview.png), and [shared rows without SD](../examples/multi-metric-shared-rows-no-sd/preview.png). These are supported layouts of this category, not separate figure categories.

## Consecutive metric clusters colored by model

Use `combo_layout: grouped-distributions` for two or more comparable metrics, with a uniform `style: bar`, `box`, or `violin`. Each metric forms a consecutive cluster of model-colored marks on one numeric axis. A compact ordinary legend names the models, using measured interior space when safe and otherwise the external top guide. Both `orientation: vertical` and `horizontal` are supported; requested metric and model orders persist. The renderer reuses the common filtering, pairing, missing-value policy, means, sample SD and distribution calculations. Raw data are required for boxes and violins; bars also accept summary means. A violin needs at least two observations in every model/metric group.

Supply `combo_units` and `combo_domains` as complete maps keyed by `metrics`. Unit descriptions and established two-endpoint scientific domains must be identical across metrics, and observations must lie within the declared domain. Similar observed values alone do not establish comparability. Do not silently normalize, align unlike units or infer bounds from observed extrema. Use independent-axis layouts when scientific definitions are unlike. Matching IDs are checked within each metric when `paired: true`; the renderer does not claim independence or require cross-metric completeness unless separately established.

The requested `style` becomes every metric's `combo_styles` when that field is omitted. An explicit `combo_styles` must contain one uniform supported style, either once or once per metric. Color is always by model. Use common `limits` and `breaks`, not `combo_limits`/`combo_breaks`. Grouped bars use a zero baseline and include zero even when `axis_policy: zoom` is requested, preserving one honest common scale. Boxes/violins show all observations and outliers; SD, when requested, is symmetric sample SD. `combo_show_sd` can select its visibility per metric. Numeric mean labels, ranking arrows, inside values, outward SD and significance brackets are unsupported; their corresponding requests are rejected. Mean and SD records remain available in the summary export regardless of overlays.

Omitted dimensions use one complete 57 × 54 mm canvas in either orientation; the four-column profile uses 42 mm width. Metric count does not multiply width or height. Endpoint glyph gutters, shared numeric axes and measured metric-label fitting divide that budget while retaining observations and original scientific scales. Numeric ticks use `axis_text_size` (6 pt by default); metric labels use `category_text_size` (6.4 pt), assigned to the appropriate axis after orientation. Tick fitting and exported typography must use the same numeric font size. Measured Arial text fitting resolves metric-axis labels; the model legend selects columns by measuring the complete Arial guide (including keys and spacing), using safe interior space or a full-figure external fallback and wrapping into rows when needed. Supplied captions wrap to the measured panel width. Impossible readable fits fail with guidance to enlarge the canvas or shorten display labels. Adapt the canvas for long labels or many models. A single observation can support a bar/box but not sample SD or violin density. The default palette is `rainbow-transparent`, retaining fixed RGB slots and distribution opacity/darkening.

Start from [the minimal configuration](../examples/grouped-distributions-box-vertical/request.json). The fixed-data synthetic gallery shows [bars](../examples/grouped-distributions-bar-vertical/preview.png), [boxes](../examples/grouped-distributions-box-vertical/preview.png), and [horizontal violins](../examples/grouped-distributions-violin-horizontal/preview.png). These are extensions of this category. For explicit empty-interval breaks on raw grouped boxes, see [the box-axis contract](multi-comparison.md#optional-broken-numeric-axis-for-boxes).

### Automatic ordinary model-guide placement

For `combo_layout: grouped-distributions`, `legend_placement: auto` is the default. The renderer measures the complete guide and the final single plotting panel on each Arial-capable export device, including both orientations. It searches horizontal, vertical and multiple-column rectangular guide frames in data-derived empty regions, maximizing surrounding clearance rather than choosing a narrow slit, while retaining at least `legend_clearance_mm: 0.8` from point edges, bars, box/violin bodies, whiskers, shown SD and the panel boundary. Conservative polygon/segment bounds can retain extra empty space. Unknown annotation geometry makes automatic placement fall back outside. This search does not change scientific limits, sample values, typography or canvas dimensions. The existing measured top guide remains the fallback when no safe interior region fits. For vertical numeric axes, its gap includes measured endpoint half-glyph height plus physical clearance, so the guide cannot cover the upper tick label. Ordinary external top guides have no border; interior model guides have a rectangular border.

Set `legend_placement: outside` to retain the external guide or `inside` to require a safe interior fit; an unsafe explicit inside request fails with a refinement message. `legend_clearance_mm` must be positive. These controls apply to grouped ordinary model guides, not the required continuous-trend statistical guide. `metric_encoding.legend_placement` records per-format panel/guide dimensions, requested/resolved placement, columns, physical/normalized bounds, occupied mark boxes and fallback reasons. Its earlier `legend_fitting` field records the external fallback guide. Saved configurations retain the requested policy and deterministically recompute placement from the retained data. See the [empty-space synthetic example](../examples/grouped-distributions-legend-space/preview.png).

Dual-axis overlays with automatic line scales reserve the complete mean symbols and bar-SD caps using a deterministic display-range expansion when needed. Values, SD and sampling units stay unchanged, and the original/effective line ranges are recorded with the affine mapping. Explicit line limits or breaks remain authoritative. If fixed geometry remains obstructed, inspect the overlay and prefer separate facets when scientifically appropriate. Facets currently omit numeric mean annotations; show means through the requested bars/line symbols and use exported summaries for their exact values.

Shared-axis mean lines use solid SD glyphs. When physical mean symbols obscure another metric’s symbol or SD cap at the same categorical model, automatically separate complete metric series by measured within-category offsets. Keep original numeric values, one common model order and centered category ticks, and record those display-only offsets. If full glyphs cannot fit within each model’s readable slot, fail with guidance to use facets or a larger established allocation. Offsets do not encode a continuous covariate or establish association.
