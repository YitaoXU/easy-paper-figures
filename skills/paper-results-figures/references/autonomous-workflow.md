# Work from a short plotting request

Use this workflow for a new dataset or a request to choose candidate figures. Infer unambiguous column mappings from inspected contents. Reuse explicit session choices for focal/reference methods, metric direction and missing-data policy; do not ask for them again. Palette colors, opacity and darkening follow the [fixed palette contract](palette-contract.md); do not retune these during autonomous layout review.

## Consult before rendering

Inspect the input read-only before deciding what to ask. Compare the request, session choices and actual data against the proposed figure. When important details remain unspecified, consult the user before rendering; a reference image or a previous dataset does not supply missing scientific meaning.

- Required scientific answers can include the metric/units and row meaning, score columns, pairing or repeated-measurement unit, better direction and one-sided hypothesis, categorical versus numeric color meaning, or handling of missing/failed predictions. Ask only about unresolved items that change the requested result. Do not choose a hypothesis from the observed winner.
- Ask about materially different displays when the request does not establish the intended comparison or deliverable: two-method paired scatter versus multiple-method distributions, one recommended figure versus a candidate set, or separate metrics versus a shared-row combination. Recommend a suitable choice based on the inspected data and give concise options. If the user already says to choose automatically, produce alternatives, or use defaults, that answers the applicable visual choice.
- Establish an output destination when none is available from the request, session or project convention. An unnamed palette can use the documented default; when a reference color is ambiguous or a new color is requested, clarify the palette/family rather than guessing an exact identity. State the default palette and figure choice in the brief update when useful.
- Bundle related questions into one short consultation (normally one to three items). A concise pre-render brief can identify the metric, observation/pairing unit, methods, selected display, color meaning and output folder. Do not require a second confirmation after the user answers. Do not turn point sizes, margins and other adaptable defaults into a questionnaire.

Wait for required answers before dependent statistics or image generation. Meanwhile, inspect ranges, grouping and availability, load the selected references, or reuse the environment cache. If the request is already clear, proceed without a redundant question. Existing figure revisions retain their established data contract unless the revision makes it ambiguous. Record resolved scientific choices and final visual settings with the external figure.

## Establish the data contract

- Inspect actual columns, values, ranges, method names, group counts and availability flags. Distinguish raw observations from means/SD or pooled scores. Exclude clearly labeled aggregate rows when analyzing raw rows, recording the filter and count.
- Establish the scientific question, number of methods and metrics, metric units and any defined domain before choosing a display. Storage layout alone does not determine the category: wide raw observations can support distributions; summary rows cannot reconstruct them. A defined domain comes from scientific meaning, not a guessed observed range.
- Compare the actual table shape and storage types with the selected renderer's contract. Use its native long/wide input when appropriate; otherwise read [input preparation](data-preparation.md) and save the smallest reproducible mapping/reshape or strict numeric conversion. Users do not need to supply a preformatted table. Preserve raw-versus-summary meaning, lexical IDs including leading zeros, covariates and full numeric precision. Check the prepared schema and pairing sets before computation. Unit interpretation, duplicate aggregation, unmatched keys or differing paired covariates require an established scientific decision, not an automatic average or row-order pairing.
- For paired comparisons, identify the sampling key, check unique method/key combinations and identical key sets. Recalculate sample and grouping counts for this input. Repeated source units may make paired differences dependent; do not inherit a previous dataset's counts or claim independence from unique row IDs.
- Preserve source values and pairings. Use an availability flag when it explicitly represents failed predictions, including numeric placeholders. Missing observations default to an error requiring a defined policy. Apply penalties only when their rule and bound are established by the user/session or an explicit metric definition and authorized missing-data policy. Do not assume zero is universally appropriate. Record imputed/penalized rows and the denominator. A missing entire row requires a saved completion step.
- Confirm higher/lower-is-better, metric units, focal method and any reference from the request or established context. A reference-like name alone does not authorize a reference subtraction or a statistical hypothesis.

## Select useful candidates

Honor a requested style or number of outputs. For a general multiple-method request with no style selected, raw data normally get box, violin and bar candidates with all observations and mean ± sample SD. Add a paired reference-difference line when a reference is established and valid pairings exist. If the user asks for one recommended figure, choose a box plot for broad/skewed distributions or a bar plot for summary-only data; do not generate extra candidates automatically.

Route explicitly among a suitable specified category, one recommended figure, and a requested small candidate set. Use the [catalog's selection boundaries](figure-catalog.md#selection-boundaries). A two-method matched-observation question about agreement or individual improvement supports paired scatter; its optional marginal histograms/KDE add distribution context while retaining the matched sample. Several-method distribution or summary questions route to the single-metric category; multiple-metric questions can use separate views or a suitable combination. Two metrics can use parallel horizontal bars, stacked vertical bars, facets or a labeled dual axis. Two or more genuinely comparable metrics can use shared-axis mean lines only with established identical units and scientific ranges, without rescaling. For a requested maximum of two or three candidates, generate only useful supported alternatives; the maximum is not a quota. Required scientific consultation precedes dependent calculation, while cosmetic defaults are resolved through measurement and preview inspection.

Skip unsupported candidates: summary scores permit bars or a requested mean line, but not distributions or reconstructed observations. Only show SD when available or computable; small/constant groups may not support a meaningful violin. For multiple requested metrics, create separate panels by default and stable method colors; use a combination only when it helps the requested comparison. For shared model labels, select `multi-metric-comparison` with `combo_layout: shared-rows` for horizontal parallel bars or `stacked-bars` for vertical panels one above the other. Larger internal values and omission of displayed SD are supported options. Establish one common ordering metric or explicit model order, rather than independently sorting each panel. `shared-axis` supports two or more mean lines only when the established units/domains match; metric colors identify the lines. Dual-axis lines omit SD by default but retain mean symbols and actual SD in records. Paired scatter remains a single matched-score comparison, not a multi-style batch.

The reusable `scripts/render_candidates.R` accepts one validated single-metric multi-comparison configuration and optional comma-separated styles. It creates independent figure folders, a batch index and an overview within the first figure folder. It reuses the normal renderer; it does not infer scientific semantics or replace this preflight. Example:

```bash
Rscript /path/to/skill/scripts/render_candidates.R /path/to/base-config.json
Rscript /path/to/skill/scripts/render_candidates.R /path/to/base-config.json box,violin
```

Set `output_prefix` to `<output-parent>/<base-name>/<base-name>`. Candidate names append `_box_points_sd`, `_violin_points_sd`, `_bar_points_sd`, or `_delta_reference_line` when appropriate. A supplied `reference` and `paired: true` enable the default difference-line candidate; explicit `line` without a reference produces a mean line. Default raw candidates use points and SD; summary candidates use SD only when a column is supplied. Explicit `show_points`, `show_sd`, `line_markers` and style choices take precedence. Clear inherited `limits`/`breaks` before switching raw to delta; the batch helper does this for its delta candidate.

## Built-in appearance, not a repeated prompt

The R scripts enforce these initial values when fields are omitted or documented as null, including the selected layout's visual profile. A normal scientific request does not need a separate list of cosmetic settings to obtain the documented gallery style. Keep new configurations minimal: provide data mappings, scientific choices, palette and requested encodings/overlays, then let the renderer resolve its typography, spacing, marks and measured guides. A current per-figure revision overrides them. A resolved configuration contains explicit values: clear optional fields to null or remove them to request recalculation on new data. Do not copy a synthetic example's ranges, selected IDs, focal hypothesis or missing-data policy to an unrelated CSV.

Dense-point threshold and spacing are starting heuristics, not scientific cutoffs. Review overlap, long labels, category count and annotation occupancy. Increase height or clearance when necessary. An existing figure family's explicit colors remain fixed across metrics even when ranking changes. The batch helper fixes its model-to-color map before rendering candidates.

Interior annotation strips use physical Arial measurements. Establish any `metric_domain` from scientific meaning rather than guessing it from the input range. Preserve the complete data/SD extent, recording original `data_limits`, display `limits` and any added empty strip. Clear inherited data/display limits before adapting to unrelated new data. Bars keep their baseline flush with the axis.

Significance is opt-in from the request or established session; it is not enabled just because a focal label exists. When authorized, use the specification's one-sided tests against every displayed comparator and all-comparators gate. Reference deltas are calculated per matched observation before SD. Never infer uncertainty from pooled means.

## Finish without further prompting

Reuse the environment cache and reusable renderers. Inspect every candidate PNG and a representative vector preview, then adjust and re-render affected figures. Check statistics against the source, pairing/penalty counts, source identity, actual dimensions, Arial embedding, measured text rotation/wrapping, proportional paired annotation frames, full color-guide occupancy, marginal sample/counts when requested, ranking direction, uncertainty visibility and annotation collisions. A successful render alone is not visual QA.

Keep each figure's PDF, editable SVG, 600 dpi PNG, final configuration, plotted values, statistics and session record together. Add concise data-handling/layout notes and a reproduction command or script; preserve a renderer/palette snapshot with any custom preprocessing so future skill edits do not change reproduction. Prefer the saved final configuration over a prose list of parameters. Keep the batch index/overview in an existing figure folder, with no loose files or shared support folder in the output parent. Report output links and material data decisions; do not require the user to request verification separately.

When input adaptation was needed, retain its source snapshot, prepared input, mappings, counts/exclusions, configuration/report and reproduction script in that same figure folder. Record any authorized scientific preprocessing separately from a shape-only conversion; the reusable adapter never aggregates or imputes. Valid native input needs no redundant conversion.

Existing figure revisions reuse their folders. Do not rerender unrelated figures merely because a default changes. Generic examples and skill text must remain free of real user data, names and paths.
