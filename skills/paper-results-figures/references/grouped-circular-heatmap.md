# Grouped circular heatmap with matched-item violins

Use `plot_type: grouped-circular-heatmap` for several methods measured on the same items, each belonging to one categorical group. This is a dense full-row compound figure, with a 180 × 168 mm default canvas, actual Arial and gray outlines. Synthetic benchmark items and generic evaluation groups are supported without domain-specific vocabulary.

## Data and scientific meaning

Supply long CSV data with `item`, `group`, `model`, `score` columns, or map those roles explicitly. Each item/model combination must occur exactly once. All models must have the same item set; each item must belong to exactly one group consistently across models. IDs are strings, including leading zeros. Missing, nonfinite, duplicate, unmatched and out-of-domain observations are errors, never silently removed, averaged, imputed or clipped. Adapt an unambiguous wide table through the shared input-preparation workflow.

Declare `metric_label`, `metric_domain` (two increasing scientific bounds), `sampling_unit` and `direction` (`higher` or `lower`). A bounded benchmark score can use [0,1]; observed extrema do not define a scientific domain. The renderer supports two to six models and one to twelve groups. Hypothesis tests remain opt-in and require an explicit focal comparison and independent item-level paired differences; a distribution or visual focal designation never establishes those assumptions. When item scores summarize repeated measurements, establish unit-level aggregation outside the renderer and disclose it.

## Encodings and defaults

- Sectors span a 278° arc starting at the top, leaving room at upper right for the model key and optional horizontal violins. Sector span is exactly proportional to group item count after common inter-group gaps. Every item has the same angular width, including single-item groups; there is no integer rounding or angular inflation.
- Default group order is largest first, ties by identity. Items sort by string identity within their group. Explicit `group_order` and `item_order` preserve scientific ordering; `item_order` defines within-group order because groups remain contiguous.
- Model order is outer-to-inner and top-to-bottom. Comparators run from weaker to stronger mean according to `direction`; the focal model is innermost and bottommost. `focus_model` defaults to the exact ID `Ours` if present. Explicit `model_order` takes precedence.
- Each tile retains one exact score. `heatmap_palette` uses the fixed continuous anchors in `palettes/palettes.json`, interpolated linearly across `metric_domain`. Default: `muted-green-blue-purple-light`. Heatmap opacity is 1.0, independent of categorical fill opacity. The center numeric key labels the domain minimum, midpoint and maximum. Direction does not reverse colors; larger numbers always use the final anchor.
- Inner group bands and the group legend use the same palette as `heatmap_palette` when `group_palette` is omitted or null. This category uses a preset’s fixed `group_categorical` slots when present, otherwise its `categorical` slots. The light green-blue-purple and blue-yellow presets each have twelve fixed coordinated group colors, coordinating larger group sets with the score colors while preserving the method slots. When another inherited preset has too few group slots, groups resolve to the fixed twelve-slot `muted-balanced-twelve` preset; this fallback is recorded in the resolved configuration. An explicit `group_palette` requires sufficient fixed group slots and never recycles or interpolates categorical colors. Group slots map sorted identities; changed group sets require a saved named map to preserve cross-figure assignments. An explicitly supplied named `group_colors` map takes precedence. Counts report unique items, not long-table rows.
- Companion violins use the same named palette as `heatmap_palette` when `palette` is omitted or null, reserving the focal hue through the shared palette contract. `color_values` accepts an established named model map; automatic requests should omit it. Categorical fill opacity is preserved. Thus a new minimal request coordinates score, model and group color families. Explicit `palette`, `group_palette`, named maps and previously resolved configurations remain authoritative; changing only the heatmap palette in a saved configuration preserves its explicit method/group choices.
- The model key is centered between the top sector start and the violin axis, using measured actual Arial widths. Each title has equal left/right horizontal clearance; the longest title has a 4 mm gap on each side. This refers to the shared axis boundary, while observed density extrema retain their scientific positions. The compound violin block ends 1.2 mm beyond the actual rightmost displayed circular item label, measured from its rotated Arial bounding box (or the tile edge if item labels are hidden). Without significance, `show_mean` defaults to true and adds a three-decimal arithmetic mean column to the right of each violin; the axis leaves the measured mean-column width plus a 2 mm gap before that column. With both means and significance hidden, the axis itself reaches the same right boundary. Means use the complete matched item sample with equal item weights; no hypothesis test is inferred. Means are hidden when `show_violin: false`. Significance replaces that column when requested; an explicitly enabled mean column together with significance is an error. Model titles use 9 pt, the side-column heading and statistics use 8 pt, score-axis ticks use 7.5 pt and the violin score-axis title uses 8.5 pt, measured in actual Arial. Circular item labels and group-guide typography remain unchanged. The axis keeps at least 35 mm width; longer titles require an established larger canvas or shorter authorized labels.
- `group_legend_placement: auto` keeps the group count legend inside for up to six groups and places it in a framed right-side guide for more than six. Explicit `center` or `right` selects that placement. A right-side guide reserves a measured Arial-width sidebar by shifting the circular center left, keeps at least 3 mm horizontal clearance from all displayed item labels and begins below the violin block. The complete requested canvas and print typography stay fixed. The center retains the score colorbar; center guide rows and the hole adapt to the selected placement. Counts remain unique-item counts.
- `show_violin: true` displays one score per matched item for each model, pooling items with equal item weights. Unequal group sizes contribute unequal numbers of items; this does not compute an equal-group average. KDE uses `nrd0` bandwidth, 512 evaluation points and observed min/max support, with closed ends at those extrema. Density is descriptive, not confidence or SD. Q1/Q3 use dashed gray segments ending at the density contour; the median is solid. Fewer than three items or constant scores get exact points/range instead of an invented violin.
- `show_significance: false` is the default. Enabling it requires `show_violin: true`, one explicitly supplied `significance_model` present in the data, and `independent_items: true` establishing that paired item-level differences are independent across items. It uses one-sided paired t-tests matching by item identity against every other displayed model: focal > comparator for `direction: higher`, focal < comparator for `direction: lower`. Group membership does not change the statistical unit; no equal-group averaging or hypothesis selection from observed results is allowed. `focus_model` alone does not authorize a test. Repeated/dependent items require an established aggregation or dependence-aware analysis outside this renderer.
- `p_adjust: holm` is the significance default, correcting across the full prespecified focal-versus-comparator family, counting untestable comparisons in the family size; explicit `none` is supported and recorded as unadjusted. Gray nested brackets appear on the right only when every comparison has a finite adjusted p-value below 0.05. Each rotated 8 pt label reads `p-value < 0.05`, with a `Holm` or `Unadjusted` heading identifying the correction. If any comparison fails that gate or cannot be tested (including degenerate variance or paired differences indistinguishable at source-scale floating precision), no brackets appear and the side guide says `Brackets omitted`. This does not assert that every individual comparison is nonsignificant. All comparisons, raw/adjusted p-values, test statistics, degrees of freedom, failures, the source-precision tolerance (eight machine epsilons times the maximum absolute paired source score) and display-gate reasons remain in the scientific records. When the correction heading is wider than a single bracket column, it sits on a separate row above the matched-item heading instead of reducing the score axis. Measured Arial bracket-label thickness and fixed nested spacing reserve the side column without automatic canvas expansion; its outer edge retains the item-label boundary plus 1.2 mm. When the resulting score axis cannot retain its 35 mm minimum width, establish a larger canvas or authorized shorter labels.
- `show_item_labels: true` retains original strings in radial labels at 5.6 pt. Automatic `label_every` uses angular pitch and fixed-size typography, always labeling the final item in each group while suppressing a neighboring label inside that stride. A dense small group may show only its endpoint identity. All tiles remain if labels are thinned. A positive integer stride can be supplied explicitly; the resolved stride is recorded. Labels exceeding the canvas or model labels exceeding the open wedge require authorized shorter IDs or larger dimensions, not smaller typography.

## Minimal request

See the [minimal JSON](../examples/grouped-circular-heatmap/request.json) and [user-style prompt](../examples/grouped-circular-heatmap/prompt.md). Specify scientific meanings and encodings, leaving appearance defaults to the renderer. `title` and `caption` are optional. `width_mm`/`height_mm` allocate the complete canvas; minimum dimensions are 160 × 155 mm. `show_violin: false` provides the heatmap alone. Do not inherit synthetic model names, domains or sampling assumptions for new data.

## Exports and review

Use `scripts/render.sh`. Export vector PDF, embedded-Arial editable SVG with a native continuous colorbar gradient and 600 dpi PNG, final configuration, exact plotted scores with tile coordinates and fills, KDE data when applicable, model n/mean/sample SD/quartiles/extrema, group means/counts and session records. Geometry records also retain measured model widths, equal-side clearances, axis endpoints, rotated item-label bounds, mean/significance-column bounds, bracket positions and label fit, group-guide placement/bounds, guide rows and selected label identities. Records retain unrounded values and state whether inference was requested, the independent item-level pairing assumption, the selected adjustment and all test/display outcomes. Reported means and quartiles use three decimals; axes use compact decimals.

Inspect raster and vector exports at final print dimensions: radial labels, model-track/violin alignment, small sectors, center/right group-guide and score-colorbar clearance, right-side means or significance brackets, enlarged violin text, ticks and font embedding. Independently recompute requested tests and corrections, counts, pairings, summaries and sector proportions from raw input. Keep replay evidence and resource identity outside the skill with the figure outputs.
